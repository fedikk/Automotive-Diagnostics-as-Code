# Contributing

## Development Branch

Active development is performed on the `dev` branch.

The `main` branch is reserved for stable project versions.

## Changes

Before submitting a change:

1. Understand the relevant architecture and requirements.
2. Implement the change.
3. Add or update tests.
4. Update documentation when required.
5. Verify that the project builds and tests successfully.

## Commit Messages

Use concise and descriptive commit messages.

Examples:

```text
feat: add diagnostic model
fix: validate duplicate DIDs
test: add UDS session tests
docs: update architecture
ci: add validation workflow
```

## Pull Requests

Pull requests should explain:

* The purpose of the change
* The implementation
* Tests performed
* Documentation changes

## Design Decisions

Significant architectural decisions should be documented using Architecture Decision Records (ADRs).
